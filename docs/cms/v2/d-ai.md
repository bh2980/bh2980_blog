# CMS v2 — D. AI 보조 작업 계획

작성일: 2026-09-28 · 상태: **D1·D2 구현(2026-10-01)** · 브랜치: `feature/cms-v2`

> 범위는 [`CMS-V2-SPEC.md`](../../../CMS-V2-SPEC.md) §5. 이 문서는 결정·구현 설계·순서·완료 조건이다. D1(slug·태그 추천)과 D2(AI 초벌 번역)는 모두 **선택 기능**이다. 키가 없으면 버튼이 보이지 않고 나머지 CMS는 그대로 동작해야 한다.

## 0. 지금 있는 것

- 필드 정의의 `actions?: readonly string[]`(`src/cms/schema/fields.ts:26`)는 자리만 있고 등록부·API·UI가 없다. 입력 교체용 클라이언트 등록부(`FIELD_INPUTS`, `field-inputs.tsx`)는 있다.
- 번역본 만들기는 `POST /entries/{id}/translations { locale }` → `contentService.createTranslation`(`src/cms/services/content-service.ts:71`)이 원문의 언어별 값·본문을 복사한 초안을 만든다. 편집 머리글의 `language-menu.tsx`에서 부른다.
- MDX 파싱·검사·직렬화: `parseMdxAst`(`mdx/parse.ts`), `analyze`(`mdx/analyze.ts`, v1 §4.4 검사), `serialize`. 기존 코퍼스 왕복 검수 `pnpm cms:migration:audit`.
- `/meta`가 컬렉션·블록 정의와 서버 제한을 내려준다. AI 사용 가능 여부도 여기에 싣는다.
- AI SDK·키 환경 변수는 아직 없다.

## 1. 결정

### 1.1 확인이 필요한 것 (명세 §7 "D2 모델·비용 한도")

착수 전에 사용자가 정한다. 괄호 안은 권장안이고, 답이 없으면 권장안으로 진행한다.

| # | 질문 | 권장안 |
| --- | --- | --- |
| Q1 | 제공자·모델 | 제공자 1곳. 추천(D1)은 작은 모델(`claude-haiku-4-5` 급), 번역(D2)은 큰 모델(`claude-sonnet-5` 급). 모델 이름은 환경 변수라 코드 변경 없이 바꾼다 |
| Q2 | 비용 한도 | DB 없이 **요청 단위 상한**만 둔다: D1 입력 8천 자·출력 512토큰, D2 문서 20만 자·조각당 출력 상한, 관리자 전용. 월 예산 누적(사용량 테이블)은 DB 이전이 필요해 v3 |
| Q3 | 태그 추천이 없는 태그를 제안해도 되는가 | 기존 태그 우선, 새 태그 이름은 최대 2개까지 "새로 만들기" 칩으로만(수락해야 `createInline` 경로로 생성) |
| Q4 | 번역 결과를 저장 전에 미리 보여 줄지 | 저장 전 확인 대화상자(제목·요약·본문 앞부분·경고 목록) 후 `초안으로 만들기`. 자동 발행 없음 |

> **2026-10-01 방향 변경.** 아래 §1.2·§1.3의 "코드 액션 등록부(`suggestSlug`·`FIELD_ACTIONS`)" 대신, 기능을 **조합 정의(DB) + 화면 자리**로 만들었다. 기능마다 코드를 짜지 않고 관리자 AI 화면에서 만들고 고친다. 구현 내용은 §5. §1.2·§1.3은 처음 계획으로 남겨 둔다. §1.4(D2 번역)는 그대로 유효하다.

### 1.2 서버 AI 계층 — 제공자 포트 + 액션 등록부

- `src/cms/ai/` 아래 서버 전용(`import "server-only"`) 모듈로 둔다. 브라우저 번들에 SDK·키가 들어가지 않음을 빌드 산출물 검사(키 이름 문자열 grep)로 확인한다.
- **제공자 포트** `AiProvider.generateJson({ system, input, schema, maxOutputTokens, signal })` 하나. 구현은 실제 제공자 어댑터 1개와 **결정적 `fake` 어댑터**(테스트·로컬 개발·브라우저 확인용, 키 불필요).
- 환경 변수(`env.d.ts`에 문서화): `CMS_AI_PROVIDER`(`anthropic`|`fake`, 없으면 꺼짐), `CMS_AI_API_KEY`, `CMS_AI_MODEL_SUGGEST`, `CMS_AI_MODEL_TRANSLATE`. `fake`는 `NODE_ENV !== "production"`에서만 허용.
- **서버 액션 등록부** `src/cms/ai/actions.ts`: `{ suggestSlug, suggestTags }`. 필드 정의의 `actions` 이름이 등록부에 없으면 정의 테스트가 실패한다(B2 `backlink` 정의 테스트와 같은 방식).
- 응답은 zod 스키마로 검증한다. 모델 출력이 스키마를 어기면 1회 재시도 후 `ai_failed`.
- 오류 코드(`error-handler.ts`·`api-error-message.ts`·`openapi.yaml`): `ai_unavailable`(503, 키 없음), `ai_failed`(502), `ai_input_too_large`(413), `ai_rate_limited`(429, 제공자 429 전달).
- `/meta`에 `ai: { actions: ["suggestSlug","suggestTags"], translate: true }`처럼 켜진 기능만 싣는다. UI는 이것만 보고 버튼을 숨긴다.
- 로그: 요청마다 액션 이름·모델·입출력 토큰 수·소요 시간만 남긴다. 본문은 로그에 남기지 않는다.

### 1.3 D1 slug·태그 추천

- **API:** `POST /api/cms/v1/ai/actions/{name}` (관리자 전용). 저장 전 글에서도 쓰므로 entry id가 아니라 **지금 폼 값**을 보낸다: `{ collection, locale, entryId?, title, summary, mdx }`. 서버가 액션별로 필요한 부분만 잘라 쓴다(본문은 앞 4천 자 + 제목들).
- **`suggestSlug`:** 영어 slug 후보 3개. 모델 결과는 `slugify`·`normalizeSlugInput`(`core/slug.ts`)을 통과한 것만 남기고, 같은 "컬렉션 + 언어" 안에서 이미 쓰이거나 예약된 주소는 뺀다(v1 주소 예약 규칙). 번역본에서도 쓸 수 있다(`localized: "inherit"`).
- **`suggestTags`:** 서버가 기존 태그 목록(id·기본 언어 이름)을 모델에 주고, 결과는 **목록 안의 id만** 받는다(목록 밖 id는 버림). 이미 고른 태그는 뺀다. 새 태그 이름은 Q3 결정대로. 태그는 공통 필드라 번역본에서는 버튼이 없다.
- **정의:** `slug`에 `actions: ["suggestSlug"]`, `tagIds`에 `actions: ["suggestTags"]`(게시글·메모).
- **UI:** `schema-fields.tsx`가 필드의 `actions`를 읽어 입력 옆에 작은 `추천` 버튼(아이콘 + 툴팁)을 그린다. 결과는 입력 아래 **칩 목록**으로만 보이고, 칩을 눌러야 값이 바뀐다(slug는 교체, 태그는 추가). 불러오는 중·실패 문구, 다시 누르면 새 요청(이전 요청 `AbortController`로 취소). 값이 바뀌어도 자동 저장 흐름은 기존 그대로다.
- 클라이언트 쪽 버튼 렌더러 등록부(`FIELD_ACTIONS`)를 `FIELD_INPUTS` 옆에 둔다. 액션 이름 → 결과 칩 렌더러.

### 1.4 D2 AI 번역 — 블록 MDX 그대로 번역 + 뼈대 검사 (2026-10-01 다시 정함)

> 처음 계획(조각 추출·자리표시 태그·다시 끼우기)은 아래 "처음 계획"으로 남긴다. 요즘 모델은 MDX 문법을 유지한 채 글자만 번역하는 것을 대부분 해내므로, **번역은 모델에 맡기고 결과는 코드로 검사한다.** v3 번역 화면(원문 틀·안내 글·원문 칸, [`v3/translation.md`](../v3/translation.md)) 위에 얹는다.

**대상.** 번역본 에디터에서 **안내 글(`:untranslated`)이 남은 최상위 블록**. 안내 글이 곧 "아직 번역 안 된 곳"이라 새 번역본·반쯤 번역한 글·원문이 바뀌어 새로 생긴 블록에 모두 쓴다. 번역할 원문은 그 블록의 안내 글을 걷어 낸 MDX(= 원문 블록 MDX)다.

**흐름(블록 하나).**
1. 블록의 원문 MDX를 그대로 보낸다. 코드·수식·Mermaid·차트 블록은 보내지 않는다(번역할 글이 없다).
2. 지시문: 사람이 읽는 글만 대상 언어로 번역하고, MDX 문법·코드·주소·속성 이름은 그대로 둔다. 콜아웃 제목·탭 이름·이미지 alt·캡션처럼 사람이 읽는 속성 값도 번역한다. 블록 정의에 `translatable` 표시를 따로 두지 않는다.
3. **검사.** 결과에 `analyze`(MDX 검사)를 돌리고, 원문과 결과의 **뼈대**를 비교한다. 같아야 하는 것: 블록·인라인 요소의 종류와 순서, 링크 주소, 이미지 `src`·`mediaId`, 코드 언어·내용, 수식, directive 이름과 사람이 읽지 않는 속성. 달라도 되는 것: 글자, 사람이 읽는 속성 값. 굵게·링크의 위치가 문장 안에서 옮겨지는 것은 허용한다(요소 수·종류·주소가 같으면 통과).
4. 통과하면 그 블록을 결과로 바꾼다(안내 글이 사라진다). 실패하면 그 블록은 안내 글로 두고 경고에 담는다. 한 블록이 틀려도 나머지는 들어간다.
5. 결과는 저장 전 편집 내용으로 들어가고 자동 저장·검토·발행 흐름은 그대로다. 안내 글이 남아 있으면 발행을 막는 v3 규칙도 그대로다.

**화면.**
- **블록 번역:** 번역 에디터에서 안내 글이 남은 블록의 손잡이 옆에 `번역` 버튼. 넣을 자리가 그 블록이라 원문 칸 짝짓기(순서 기준, 블록을 더하거나 빼면 어긋날 수 있다)에 기대지 않는다.
- **전체 번역:** 번역 에디터 툴바의 `모두 번역`. 안내 글이 남은 블록을 몇 개씩 묶어 차례로 보낸다(Vercel 함수 시간 제한). 진행률·취소, 끝나면 실패한 블록 수와 위치.
- 원문 칸(읽기 모드)의 블록 버튼은 두지 않는다. 필요해지면 "짝이 되는 번역 블록에 아직 안내 글이 있을 때만" 보인다.
- 원문 변경 비교 대화상자의 블록별 `다시 번역`은 뒤로 미룬다(바뀐 블록을 안내 글로 되돌리는 동작이 먼저 필요하다).

**AI 구조와의 연결.** 기본 기능 `번역`(생성 방식)으로 둔다. 연결·모델은 기능마다 고르고(번역은 큰 모델), 지시문(문체·번역하지 않을 용어 목록)은 AI 화면에서 고치며, 실행할 때 추가 요청(예: 존댓말로)을 받는다. 실행은 일반 자리 흐름(후보·글·메모)이 아니라 위 전용 흐름이다.

**만들 것.** 블록 나누기·뼈대 비교(원문 비교 `source-diff.ts`의 블록 나누기와 MDX 파서를 쓴다), 번역 API(블록 몇 개를 받아 번역·검사한 결과와 경고를 돌려준다), 에디터의 블록 버튼·툴바 버튼·진행률.

MDX 원문 전체를 모델에 넘기고 구조가 보존되길 기대하지 않는다. **번역할 글자만 조각으로 뽑아 번역하고 원래 트리에 다시 끼운다.** 구조가 바뀔 수 없으므로 명세의 "directive·코드 펜스·이미지 속성·링크 주소 보존"이 설계로 보장된다.

- **추출(`src/cms/ai/translate/segments.ts`, 순수 함수·브라우저/서버 공용):** `parseMdxAst` 트리를 돌며 문단·제목·목록 항목·표 셀·인용·directive 라벨 단위로 조각을 만든다.
  - 번역 대상: 텍스트, 강조·링크의 글자, 이미지 `alt`·캡션, 블록 정의에서 **번역 대상으로 표시한 속성**(콜아웃 제목, 접기 제목, 탭 이름, 툴팁 설명 등). B3 정의에 `translatable: true` 속성 표시를 더해 목록을 정의에서 만든다.
  - 번역 제외: 코드 펜스·인라인 코드 내용, 수식, Mermaid·차트 원문, URL·링크 주소, directive·JSX 이름과 그 밖 속성, frontmatter 키, HTML 주석.
  - 조각 안의 인라인 구조는 자리표시 태그로 바꾼다: `**굵게** [링크](/a)` → `<b1>굵게</b1> <a2>링크</a2>`, 인라인 코드·수식은 `<c3/>` 같은 빈 태그. 어순이 바뀌는 한→영 번역에서도 서식을 옮길 수 있다.
- **복원(`reinject.ts`):** 번역된 조각의 자리표시 태그 집합이 원본과 같은지(이름·개수·중첩) 검사하고 트리에 끼운 뒤 `serialize`. 태그가 어긋난 조각은 그 조각만 재요청 1회, 그래도 어긋나면 **원문 그대로 두고 경고**에 담는다(초안 전체를 버리지 않는다).
- **검사:** 결과 MDX에 `analyze`(v1 §4.4)를 돌리고, 추가로 원문과 결과의 "글자를 뺀 트리 골격"이 같은지 비교한다. 실패하면 초안을 만들지 않고 대화상자에 오류를 보인다(명세 "초안에 넣기 전에 알린다").
- **나누어 호출:** Vercel 함수 시간 제한을 피하려고 서버가 문서 전체를 한 요청에서 번역하지 않는다.
  1. 브라우저가 원문의 최신 초안에서 조각을 뽑아 약 6천 자 묶음으로 나눈다(`chunk.ts`).
  2. 묶음마다 `POST /api/cms/v1/ai/translate { sourceLocale, targetLocale, segments: [{id, text}] }` → `{ segments: [{id, text}] }`. 서버는 묶음 크기·개수를 다시 검사하고 제공자를 부른다. 동시 2개, 진행률 표시, 취소 가능, 묶음 단위 재시도.
  3. 제목·요약은 첫 묶음에 조각으로 함께 넣는다.
  4. 복원·검사 뒤 확인 대화상자(Q4) → `POST /entries/{id}/translations { locale, draft: { title, summary, mdx } }`.
- **`createTranslation` 확장:** 선택 필드 `draft`가 있으면 복사 대신 그 값을 쓴다. 서버가 `analyze`를 다시 돌리고(브라우저 결과를 믿지 않는다) 언어별 값 외 필드는 받지 않는다(`invalid_input`). `draft` 없는 기존 동작은 바이트 불변.
- **프롬프트:** 대상 언어, 기술 블로그 문체, 자리표시 태그를 그대로 둘 것, 조각을 합치거나 나누지 말 것, 번역하지 않을 고유 명사는 그대로. 조각 글자는 데이터로만 다루도록 구분자로 감싼다(본문 속 지시문이 프롬프트를 바꾸지 않게).
- **UI:** `language-menu.tsx`의 `번역본 만들기`를 작은 대화상자로 바꾼다: `원문 복사`(기본, 지금 동작) / `AI 초벌 번역`(`/meta`의 `ai.translate`일 때만). 진행률·취소·경고 목록(원문으로 남은 조각 수와 위치).

## 2. 순서와 오케스트레이션

### 2.1 작업자에게 줄 공통 지시

- `feature/cms-v2`, 깨끗한 작업 트리에서 시작. C 결과(에디터·블록 정의·MDX 왕복)를 바꾸지 않는다.
- 제공자 SDK import는 `src/cms/ai/providers/*`에만. 스키마 정의(`src/cms/schema/**`, `src/cms/blocks/**`)에는 이름·불리언만 더한다.
- 테스트는 `fake` 제공자로만. 네트워크 호출하는 테스트 금지.
- 커밋·푸시하지 않고 변경 파일·실행한 게이트 결과를 보고한다.

## 3. 테스트 계획

- **D0:** 키 없음 → `/meta.ai` 비어 있음·액션 API `ai_unavailable`; `fake`가 production에서 거부; 등록부에 없는 `actions` 이름이면 정의 테스트 실패; 모델 출력 스키마 위반 → 재시도 → `ai_failed`.
- **D1:** slug 후보 정규화·중복 제외·같은 언어 기존 주소 제외; 태그 결과 중 목록 밖 id 버림·이미 고른 태그 제외; 입력 상한 초과 `ai_input_too_large`; UI는 칩을 누르기 전에 폼 값이 바뀌지 않음.
- **D2 핵심(가장 중요):**
  - **코퍼스 항등 번역:** 기존 49편 전체에 대해 "받은 글자를 그대로 돌려주는" `fake`로 추출 → 복원하면 결과 MDX가 원문과 **바이트 동일**. (`corpus-roundtrip`과 같은 코퍼스 사용)
  - **코퍼스 변형 번역:** 글자를 대문자·역순 등으로 바꾸는 `fake`로 돌렸을 때 골격 비교 통과, 코드 펜스·인라인 코드·URL·수식·Mermaid·차트·directive 이름과 비번역 속성은 바이트 동일, `analyze` 오류 0.
  - 자리표시 태그 누락·중복·순서 바뀜·새 태그 추가 → 그 조각만 원문 유지 + 경고.
  - 묶음 나누기: 조각이 묶음 경계에서 쪼개지지 않음, 한 조각이 상한보다 크면 문장 단위로 나누지 않고 단독 묶음(상한 초과 시 `ai_input_too_large`).
  - 모델이 조각 id를 빠뜨리거나 더한 응답은 스키마 오류로 처리.
- **B-2:** `draft` 있는 번역본 만들기의 서버 재검사(깨진 MDX 거부, 공통 필드 거부), `draft` 없는 기존 테스트(`translations.test.ts`) 불변, 취소 시 초안이 만들어지지 않음.
- **브라우저(CDP, `fake`):** slug·태그 추천 → 칩 수락 → 저장 값 확인; 번역본 `AI 초벌 번역` → 진행률 → 확인 대화상자 → 초안 생성 → 에디터에서 코드·표·이미지·콜아웃이 그대로인지; 키 없음 설정에서 버튼이 모두 사라지는지. 산출물은 `.pi/d-review/`.
- **실제 제공자(통합 단계 1회):** 짧은 글·코드·표·콜아웃이 섞인 글 각 1편을 `en`으로 번역해 경고 수·소요 시간·토큰 수를 기록한다.

## 4. 완료 조건

- 키가 없으면 AI 버튼이 보이지 않고 기존 기능·테스트가 그대로다.
- slug·태그 추천은 버튼을 눌렀을 때만 호출되고, 칩을 수락해야 값이 바뀐다.
- AI 초벌 번역은 코퍼스 항등 번역에서 원문을 바이트 그대로 복원하고, 변형 번역에서도 MDX 구조·코드·주소·비번역 속성을 바꾸지 않는다. 검사 실패는 초안을 만들기 전에 알린다. 자동 발행하지 않는다.
- 제공자 SDK·키가 브라우저 번들·API 응답·로그에 없다.
- 전체 테스트·타입 검사·Biome·빌드·`cms:migration:audit` 통과, 브라우저 확인, 최종 Opus 리뷰의 P0·P1 해결.
- 명세 §5·§7·§9와 이 문서 §5(구현 결과)를 갱신한다.

## 5. 구현 결과

### 5.0 기능 목록 고정 (2026-10-01 정리)

화면 자리가 4곳(+SEO 탭)으로 정해져 있고 결과가 그려지는 모양도 정해져 있어, 사용자가 "새 기능"을 만드는 것은 사실상 지시문만 다른 복사본이었다. 그래서 **기능 목록을 코드로 고정**하고(`src/cms/ai/builtins.ts`, 11개: 주소·요약·태그·카테고리·검색 제목·검색 설명·대체 텍스트·캡션·파일 이름·코드 블록 정규식 생성·번역. 미디어 화면의 기본 대체 텍스트·기본 캡션은 따로 기능을 두지 않고 대체 텍스트·캡션 추천을 같이 쓴다(`SHARED_SLOT_TARGETS`)), AI 화면에서는 기능마다 켜기·요청 받기·연결·모델·보낼 내용·지시문·기준 확률·최대 개수·검사만 고친다. 이름·자리·대상·결과·적용·방식·판단 선택지·검사 종류는 기능 정의가 정하고, 저장값보다 앞선다(`withBuiltin`). `새 기능`·삭제는 없앴다. **자리(연결 장치)가 여럿 생기면 그때 자리 기반으로 사용자가 기능을 더하게 넓힌다.**

**검사.** 종류는 다섯 가지(`형식`=정규식, `길이`=최대 글자 수, `중복 없음`=같은 필드에서 다른 항목이 쓰는 값 제외, `있는 값만`=선택지에 있는 값만, `정규식 실행`=올바른 정규식이고 대상 코드에서 한 곳 이상 찾음). 기능마다 정해 둔 검사가 편집기에 모두 보이고, 각각 켜고 끄며 형식·길이 값을 고친다. 코드가 몰래 거는 검사나 값 고치기(예전의 `slugify`)는 없다. 대상 자리는 검사 재료만 준다(`targets.ts`: 주소 필드 → 이미 쓰는 값, 연결·선택 필드 → 선택지, 코드 블록 → 코드). 파일 이름의 확장자는 검사가 아니라 미디어 자리가 적용할 때 붙인다. 예전 모양(`check` 하나 + `maxLength`)으로 저장한 정의는 읽을 때 검사 목록으로 옮긴다.

**요청 받기.** 켠 기능은 버튼을 누르면 `추가 요청` 입력이 먼저 열리고, 적은 요청이 고정 지시문 뒤에 "이번 요청(위 지시보다 우선)"으로 붙는다(자료가 아니라 지시문 쪽). 기본으로 요약·검색 제목·검색 설명·대체 텍스트·캡션·접기 규칙이 켜져 있다.

### 5.1 D1 — 조합 정의 + 화면 자리 (2026-10-01)

**구조.** 기능 하나 = 붙는 곳(slot)·대상(target)·방식(engine)·연결(providerId)·모델(modelName)·보낼 내용(inputs)·결과 모양(result)·적용 방식(apply)·결과 검사(check)·지시문(prompt). 연결을 비우면 방식에 맞는 첫 연결, 모델을 비우면 그 연결의 기본 모델을 쓴다. 판단 방식이면 여기에 선택지 출처(options)·고르는 방식(pick)·기준 확률(threshold)·최대 개수(maxCount)가 붙는다. 코드는 선택지만 가진다.

**방식.**
- `생성`(generate): 대화 모델이 JSON 모양으로 답한다. 결과는 후보·긴 글·메모.
- `판단`(decide): System One 모델(TypeSafe Jev. TypeSafe `https://api.typesafe.ai/v1/systemone` + `jev-latest`, 또는 OpenRouter `…/api/alpha/decisions` + `typesafe/jev-1.13`. 둘 다 `state`·`model`·`questions` → `answers` 모양)에 선택지를 묻는다. `여러 개 고르기`는 선택지마다 noul 질문을 동시에, `하나 고르기`는 choice 질문 하나로 묻는다. 기준 확률 이상인 선택지만 확률 높은 순으로 후보가 되고, 확률은 화면에 보이지 않는다. 선택지 출처는 태그·카테고리·필드 선택 목록(select·조건부 필드)·직접 적은 목록이다. 이미 고른 값은 묻지 않는다. 판단 모델은 이미지를 읽지 못하고 글을 만들지 않는다. 자료에 따르면 영어에서 가장 정확하므로 한국어 글은 AI 화면의 `시험`으로 확인한다.

**자리 4곳.** 필드 옆(`schema-fields.tsx`, 읽기 전용 필드 제외), 본문 이미지 alt·캡션(`image-node-view.tsx`의 `이미지 설정`, 미디어 라이브러리 이미지와 이 사이트 경로 이미지), 코드 블록 정규식 규칙(`rules-panel.tsx`, 후보를 누르면 글자 접기 규칙 추가), 미디어 파일(`media-library.tsx`, 이름은 바로 바꾸고 기본 alt·캡션은 입력에 채움).

**바뀐 것.** 미디어 `PATCH`가 `filename`을 받는다(보이는 이름만. 저장 주소와 이미 올린 첨부 파일의 내려받기 이름은 그대로). `/meta.features.ai`. 필드 정의의 `actions`는 없앴다(자리가 필드 이름으로 연결). AI 관련 환경 변수는 개발용 `CMS_AI_FAKE`만 있다.

**확인.** 전체 `vitest`(1183개)·`tsc`·`pnpm build` 통과, Biome은 원래 있던 2개 외 오류 없음, 브라우저 번들에 키 처리 코드 없음. 테스트 DB의 격리 스키마 + 가짜 연결로 브라우저 확인: 연결 저장(키 끝 네 글자만 표시, 응답에 원문 없음), 판단 방식 편집, 태그·카테고리 판단 추천과 적용, 주소·요약 추천, 코드 접기 규칙 추가, 새 기능 저장 후 편집 화면 메뉴. 이미지·미디어 자리는 실 R2 업로드가 필요해 테스트로만 확인했다.

**남은 것.** 지시문 이전 판 보관, 자동 실행 자리, 제목 필드 자리, 원문 변경 블록의 `다시 번역`, 실제 서비스로 번역 품질 확인.

### 5.2 D2 — 본문 번역 (2026-10-01)

§1.4대로 만들었다.

- **기능:** 기능 목록의 `번역`(자리 `body`, 생성 방식, 요청 받기 켬, 검사 `구조 유지`). 연결·모델·지시문은 AI 화면에서 고친다. `시험`은 예시 MDX와 대상 언어로 번역 API를 부른다.
- **구조 검사:** `src/cms/core/translation/skeleton.ts`의 `compareStructure`. 글자와 사람이 읽는 속성(`title`·`label`·`alt`·`caption`·`content`·`defaultValue`)만 달라도 되고, 요소 종류·순서, 링크 주소, 코드·수식·인라인 코드, 그 밖 속성은 같아야 한다. 굵게·링크가 문장 안에서 옮겨지는 것은 허용한다. 검사를 끄면 MDX로 읽을 수 있는지만 본다.
- **API:** `POST /api/cms/v1/ai/translate`(블록 8개·블록당 3만 자까지, 동시 3). 블록마다 `mdx` 또는 `error`. 한 블록의 형식 오류는 그 블록만, 키·크레딧·요청 수 문제는 요청 전체가 오류다.
- **화면:** 번역본 에디터에서만. 안내 글이 남은 블록의 손잡이 옆 `번역` 버튼, 툴바의 `모두 번역`(추가 요청 입력 → `번역 시작`, 진행률 `번역 중 n/전체`, 누르면 멈춤). 번역 단위는 블록 하나이고 목록은 항목 하나다(항목은 그 항목만 든 목록으로 감싸 보내고, 돌아온 목록에서 항목을 꺼낸다). 콜아웃·인용구 안 블록은 그 블록만 보낸다. 모두 번역은 단위를 4개·1만 2천 자씩 묶어 두 요청씩 보낸다. 결과는 원래 블록(JSON이 같은 것)을 찾아 그 자리에 같은 모양으로 들어갈 때만 바꾸고(목록을 쪼개지 않는다), 그사이 고친 블록은 바꾸지 않는다. 원문 창 표시는 블록 종류로 짝지어(최장 공통 부분열) 번역본 블록 수가 달라도 밀리지 않고, 목록은 항목 단위로 표시한다. 검사에 걸린 블록은 안내 글로 남고 끝에 개수를 알린다.
- **에디터:** `CmsEditor`에 `blockActions`(손잡이 옆 동작)와 `onEditor`(바깥에서 문서 전체 작업)를 더했다.
- **확인:** 구조 검사·서버 번역·안내 글 걷어 내기(원문 틀 → 원문 블록 MDX 왕복)·목록 항목/콜아웃 안 블록 바꾸기·원문 창 짝짓기 테스트. 전체 `vitest` 통과. 브라우저 확인은 사용자 개발 서버가 같은 작업 폴더에서 떠 있어 하지 못했다(같은 `.next`를 두 서버가 쓰면 캐시가 깨진다).
