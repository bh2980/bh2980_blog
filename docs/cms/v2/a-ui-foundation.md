# CMS v2 — A. UI 기반 작업 계획

작성일: 2026-09-27 · 상태: **구현 완료(2026-09-27)** · 브랜치: `feature/cms-v2`

> v2 전체 범위와 결정 기록은 [`CMS-V2-SPEC.md`](../../../CMS-V2-SPEC.md)에 있다. 이 문서는 그중 A(A0~A4)의 구체적인 작업 계획이다. 여기에 적지 않은 동작은 v1 명세 [`CMS-SPEC.md`](../../../CMS-SPEC.md)를 따른다.

## 1. 원칙

- **shadcn에 있는 컴포넌트를 우선 쓴다.** 직접 만든 UI는 shadcn에 대응하는 것이 없을 때만 둔다. 필요한 컴포넌트는 shadcn CLI로 받아 설치한다(사용자 허가 2026-09-27).
- 색은 shadcn 디자인 토큰(`bg-background`, `bg-muted`, `border-border`, `text-muted-foreground` 등)만 쓴다. `neutral-800` 같은 직접 지정 색을 관리자 화면에 남기지 않는다.
- 밝은·어두운 테마를 모두 지원한다(v1 명세 §3.1과 같음).

## 3. A0 — Base UI 전환·토큰·부품 통일

**Base UI 전환.** shadcn은 2026-07부터 새 프로젝트의 기본 primitive를 Base UI로 바꿨다. Radix도 계속 지원하지만 이 프로젝트는 Base UI로 옮긴다. [변경 기록](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)

- 대상: `src/components/ui`의 컴포넌트 전체. 블로그 화면도 11종(alert·badge·button·chart·collapsible·multi-select·popover·separator·sheet·tabs·tooltip)을 쓰므로 함께 옮긴다.
- 방법: `components.json`을 Base UI 기준으로 바꾸고, 사용 중인 컴포넌트를 CLI로 다시 받는다. 기존 파일의 이 저장소 전용 수정(차트 반응형·팔레트, Callout 관련, native-select·sheet 수정 등)은 git diff로 확인해 새 파일에 다시 적용한다. 공식 안내의 마이그레이션 스킬은 참고만 하고, 컴포넌트 단위로 커밋한다.
- 가장 큰 API 차이: `asChild` → `render`. 호출부를 모두 바꾼다.
- 완료 후 `@radix-ui/*` 의존성을 제거한다. Base UI에 대응이 없어 Radix를 남겨야 하는 컴포넌트가 있으면 이 문서에 이유와 함께 적는다.
- `cmdk` 기반 `Command`는 primitive와 무관하게 유지한다.
- 공식 컴포넌트가 아닌 `multi-select`는 shadcn `Combobox`(다중 선택)로 바꿀 수 있는지 확인한다.
- 블로그 공개 화면은 라이트·다크·모바일에서 회귀를 확인한다.

**부품 대응표.**

| 현재 | shadcn |
| --- | --- |
| 목록 `<table>` | **Data Table** (`Table` + `@tanstack/react-table`, 서버 페이지·정렬·필터 모드) |
| `<input type="checkbox">` | `Checkbox` |
| `NativeSelect` | `Select` |
| `<details>` 팝업 | `Popover` |
| 컬럼 설정·블록 메뉴 | `DropdownMenu` |
| `<input type="date">` | `Calendar`(범위) + `Popover` |
| 태그·카테고리 다중 선택 | `Combobox` 또는 `Command` + `Popover` |
| `admin-sidebar`·`admin-mobile-navigation` | `Sidebar` (접기·모바일 시트 포함) |
| 삭제 등 위험 작업 확인 | `AlertDialog` (일반 입력 대화상자는 `Dialog`) |
| 페이지 이동 | `Pagination` |
| 로딩·빈 결과 | `Skeleton`·`Spinner`·`Empty` |
| 편집 화면 상단 경로 | `Breadcrumb` |
| 에디터 툴바 | `ToggleGroup` + `Tooltip` |
| 폼 라벨·오류 | `Field`·`Label` |
| 기본 `<button>` | `Button` |

**완료 조건.** 관리자 화면에 기본 입력 요소, `<details>` 팝업, 직접 지정 색이 없다. 라이트·다크 모두 브라우저에서 확인한다. 기존 테스트·타입 검사·빌드가 통과한다.

## 4. A1 — Data Table과 엑셀식 헤더 필터

- 목록을 shadcn Data Table로 바꾼다. 검색·정렬·페이지·필터는 v1처럼 서버에서 처리한다(TanStack의 manual 모드). 행 선택·컬럼 표시·순서도 Data Table 상태로 다루고 `/preferences`에 저장한다.
- 각 컬럼 헤더에 ▾를 두고, 누르면 정렬과 필터를 함께 다루는 팝업을 연다.

| 컬럼 | 팝업 |
| --- | --- |
| 제목 | 오름·내림 정렬, 제목 검색 |
| 상태 | 초안·발행·보관 체크 목록 + `수정 중`·`예약됨` (상단에서 이동) |
| 카테고리·태그 | 검색 가능한 체크 목록, 모두 선택/해제 |
| 생성·수정·발행일 | 정렬, 날짜 범위(서울 날짜) |
| 주소(slug) | 정렬, 텍스트 검색 |
| 폴더 | 표시만. 폴더는 사이드바 탐색으로 거른다 |

- 상단에는 전체 검색(본문 포함 옵션), 적용된 필터 칩(`상태: 초안, 발행 ✕` … `모두 지우기`), 저장된 보기(A4), `새로 만들기`만 둔다.
- 필터가 걸린 헤더는 아이콘 모양을 바꿔 색만으로 구분하지 않는다.
- **숨긴 컬럼에 걸린 필터도 칩으로 계속 보인다.**
- 컬럼별 필터 종류는 설정 표 하나에서 정한다. B1이 들어오면 스키마에서 이 표를 만든다.
- 필터 의미(다른 필터 AND, 같은 필터 OR), URL 반영, 뒤로 가기 복구는 v1과 같다.
- 상태 필터에서 `휴지통`을 뺀다(A3로 이동).

## 5. A2 — 오른쪽 클릭 메뉴

shadcn `ContextMenu`를 쓴다.

| 대상 | 메뉴 |
| --- | --- |
| 사이드바 폴더 | 새 하위 폴더 · 이름 변경 · 이동 ▸ · 삭제 |
| 사이드바 빈 곳·목록 빈 곳 | 새 폴더 · 새 글 |
| 목록의 글 | 열기 · 새 탭에서 열기 · 복제 · 폴더로 이동 ▸ · 태그 추가 ▸ · 보관 · 휴지통으로 |
| 여러 항목 선택 후 선택된 행 | 위 메뉴를 선택 전체에 적용(`3개 항목` 표시). 기존 `/bulk` 사용 |
| 목록의 폴더 행 | 열기 · 이름 변경 · 삭제 |
| 휴지통 항목 | 복원 · 영구 삭제 |
| 미디어 | 상세 · 사용처 · 삭제 |

- 키보드: Shift+F10·메뉴 키로 연다. `F2` 이름 변경, `Delete` 휴지통으로 이동(확인 후).
- 마우스를 올려야 보이던 아이콘 버튼은 항상 보이는 `⋯` 버튼 하나로 바꾸고 같은 메뉴를 연다. 오른쪽 클릭만으로는 발견하기 어렵고 터치에서 쓸 수 없다.
- 선택하지 않은 행을 오른쪽 클릭하면 그 행만 대상으로 한다. 선택 상태는 바꾸지 않는다.

## 6. A3 — 휴지통

- 사이드바의 미디어·템플릿 아래에 `휴지통` 메뉴와 항목 수를 둔다.
- 전용 화면에 컬렉션 탭(게시글·메모·카테고리·태그·모음집)을 두고 컬렉션별 목록 API를 호출한다.
- **일괄 영구 삭제**를 추가한다. `/bulk`에 `permanentDelete` 작업을 추가하고 항목마다 참조 검증을 한다. 결과는 항목별 성공·실패와 사유(`사용 중: ○○`)를 보여주고 실패 항목만 다시 실행할 수 있다. 한 번에 최대 100개, 별도 확인 대화상자를 거친다. (v1 §5.3의 "일괄 영구 삭제는 v1에서 제공하지 않는다"를 대체한다.)
- 자동 비우기는 v2에서 하지 않는다([`CMS-V2-SPEC.md`](../../../CMS-V2-SPEC.md) §8 v3 메모).

## 7. A4 — 이름 붙인 저장된 보기 (2026-09-27 제거)

> 구현했다가 사용자 판단으로 뺐다. 목록 조건은 URL에 남으므로 자주 쓰는 조건은 즐겨찾기로 충분하다. 아래는 당시 계획이다.


- 현재 검색·필터·정렬·컬럼 설정을 이름 붙여 저장한다. **폴더는 포함하지 않는다**(2026-09-27 결정). 같은 보기를 어느 폴더에서든 쓴다.
- `/preferences`의 컬렉션 설정에 `views`를 추가한다. 보기마다 ID·이름·순서를 둔다.
- 테이블 위에 보기 목록(`전체 · 수정 중인 글 · … · ＋`)을 둔다. 보기를 연 뒤 조건을 바꾸면 `변경됨 · 저장 / 새 보기로 저장`을 보여준다.
- 이름 변경·삭제·순서 변경은 A2 메뉴로 한다. (v1 §3.2의 "저장된 보기 화면은 v1에 추가하지 않는다"를 대체한다.)

## 8. A 작업 순서

A0 → A1 → A2 → A3 → A4. API 변경(`/bulk` `permanentDelete`, `/preferences` `views`)은 OpenAPI와 계약 테스트를 함께 갱신한다.

## 9. 확인했던 것

- **Base UI에 대응이 없어 Radix를 남긴 컴포넌트:** 없다. 저장소의 `@radix-ui/*` 직접 의존성은 모두 지웠다. `cmdk`(Command)가 내부에서 `@radix-ui/react-dialog`를 쓰는 것만 간접 의존성으로 남는다.
- **`multi-select` → `Combobox`:** 대체했다. `src/components/multi-combobox.tsx`(shadcn Combobox 다중 선택 래퍼)를 블로그 메모 태그 필터·일괄 작업·속성 패널 태그에 쓴다.
- **`components.json` style:** `base-vega`. 기존 `new-york`과 모서리(`rounded-md`)·그림자(`shadow-xs`)가 같은 Base UI 스타일이다.

## 10. 구현 결과 (2026-09-27)

| 항목 | 결과 |
| --- | --- |
| A0 | 관리자·에디터 `.tsx`에서 직접 지정 색, 기본 checkbox·select·`<details>`·기본 `<button>`을 없앴다. 관리자 레이아웃에 `next-themes`·`TooltipProvider`·shadcn `Toaster`를 두고 라이트·다크를 지원한다. 목록·미디어·템플릿·휴지통은 shadcn `Sidebar` 기반 공통 셸(`shared/admin-shell.tsx`)을 쓴다 |
| A1 | TanStack Table v9(`useTable`, 컬럼 표시·순서·행 선택)와 shadcn `Table`로 목록을 바꿨다. 컬럼 헤더 팝업에서 정렬과 필터(제목·주소 텍스트, 상태·수정 중·예약됨, 태그·카테고리, 날짜 범위)를 다룬다. 설정 표는 `list-columns.ts`. API에 `titleContains`·`slugContains`를 추가했다 |
| A2 | `shared/action-menu.tsx`가 같은 메뉴 정의를 오른쪽 클릭(`ContextMenu`)과 `⋯`(`DropdownMenu`)에 함께 그린다. 사이드바 폴더·빈 곳, 목록 행·폴더 행·빈 곳, 휴지통 행, 미디어 타일, 템플릿 목록, 저장된 보기에 붙였다. 선택한 행을 오른쪽 클릭하면 선택 전체가 대상이다. F2(이름 변경)·Delete(휴지통·삭제 확인) 키를 지원한다 |
| A3 | `/admin/trash` 전용 화면(컬렉션 링크 탭), 사이드바 배지, `POST /bulk` `permanentDelete`(항목별 참조 검증, 실패 시 `usages`로 `사용 중: ○○` 표시)를 추가했다. 목록의 상태 필터에서 휴지통을 뺐다 |
| A4 | 구현 후 제거(2026-09-27). 화면·`/preferences`의 `views`·테스트를 모두 걷어냈다 |

**계획과 다르게 한 것.**

- **날짜·시각 한 칸 입력:** 예약 일시는 shadcn `Input type="datetime-local"`로 두었다. shadcn에 날짜+시각 선택기가 없고, 서울 시각 문자열·미래 제한(`max`)과 기존 동작을 그대로 지키기 위해서다. 날짜 범위 필터(목록·미디어)는 계획대로 `Calendar` 범위 + `Popover`다.
- **휴지통 컬렉션 탭:** `Tabs` 대신 `aria-current`가 붙은 링크 묶음이다. 컬렉션 사이 이동(내비게이션)이라 링크가 의미상 맞고, 머리글의 Base UI `Tabs`가 서버·브라우저 ID 불일치(hydration 경고)를 냈다.
- **오른쪽 클릭 메뉴는 hydration 뒤에 붙인다:** 서버에서 렌더한 Base UI `ContextMenu`가 뒤따르는 요소의 `useId`를 서버와 다르게 만들었다(사이드바 빈 곳 메뉴에서 재현). `ActionContextMenu`는 hydration 전에는 트리거 요소만 그리고, 그 뒤에 메뉴를 붙인다.
- **링크는 `Button`이 아니라 `buttonVariants`:** Base UI `Button`에 `<a>`를 렌더하면 `role="button"`이 붙는다. 링크는 클래스만 입힌 `<a>`·`<Link>`로 둔다(블로그 첫 화면 버튼, 모바일 메뉴 링크 포함). 블로그 모바일 메뉴는 `SheetClose` 대신 제어형 `Sheet`로 닫는다.
- **슬래시·내부 링크 제안 목록:** shadcn `Command`로 그리되 포커스와 방향키는 에디터가 맡는다(강조 항목만 `value`로 전달). 한글 IME 조합 중 포커스를 뺏지 않기 위해서다.
- **MDX Tooltip 설명:** Base UI Tooltip은 `role="tooltip"`·`aria-describedby`를 붙이지 않아 설명을 `sr-only` 텍스트로 트리거에 연결했다.

**남은 것(A 범위 밖).**

- 블로그 코드 블록의 복사 버튼(`src/components/mdx/copy-button.client.tsx`)은 기본 `<button>`이다. 공개 블로그 부품이라 A에서 다루지 않았다.
- shadcn `Pagination` 링크는 Base UI `Button`을 써서 `role="button"`이다. 목록은 페이지를 클라이언트에서 바꾸므로 그대로 둔다.

**검증.** 타입 검사·Biome·전체 테스트(115개 파일)·프로덕션 빌드 통과. 격리 스키마(`cms_m6_*`, 테스트 DB)와 개발용 인증 우회로 목록·헤더 필터·저장된 보기·오른쪽 클릭 메뉴·휴지통 이동/복원·폴더 생성·편집 화면을 라이트·다크·모바일 폭에서 브라우저로 확인했다. 운영 DB에는 쓰지 않았다.

## 11. 디자인 개편 (2026-09-27)

A0~A3을 끝낸 뒤 화면이 "기존 구조에 shadcn 기본값을 입힌" 수준이라 전체 위계를 다시 잡았다. 세 방향(조용한 작업 도구 / 종이 같은 에디토리얼 / 문서 워크스페이스)을 [디자인 캔버스](https://claude.ai/artifact/UMXMJ8bAM8hKqrTg1xznaB)로 비교하고, **A "조용한 작업 도구"(Linear·Vercel 계열)를 기본 틀로, 편집 화면은 본문 중심**으로 정했다.

**원칙.**

- **글꼴:** 블로그와 같은 Pretendard. 관리자 레이아웃의 `font-sans`(로드되지 않는 Inter로 떨어지던 원인)를 뺐다. 표의 숫자·날짜는 자릿수를 맞춘다(`.tabular`).
- **색:** 관리자 전용 토큰을 `html:has(.cms-admin)`에 둔다(팝업이 body로 포털되므로 문서 전체에 건다). 중립은 zinc 계열, 강조색은 indigo 하나. 블로그 토큰은 건드리지 않는다.
- **밀도:** 본문 14px, 표 행 44px, 머리글 52px. 테두리는 행 사이 가는 선만 쓰고 표를 상자로 감싸지 않는다.
- **위계:** 화면마다 강조 버튼은 하나(`새 글`, `발행하기`). 나머지는 흐린 고스트 버튼. 상태는 아이콘 모양 + 글자로 보여 준다(색만으로 전달하지 않는다).

**배치.**

- **셸:** 사이드바 위에 사이트 표시, 아래에 `블로그 보기`·테마 전환. 머리글은 `제목 + 개수 · 검색 · 새 글`만 둔다.
- **목록:** 필터가 있을 때만 칩 줄, 선택이 있을 때만 일괄 작업 줄이 나타난다. 컬럼 설정·페이지 크기·페이지 이동은 아래 한 줄에 모았다. 태그는 칸 폭에 들어가는 만큼 보이고 나머지는 `+N`(열 너비를 바꾸면 다시 잰다).
- **편집:** 머리글 왼쪽은 `목록으로 / 제목 / 상태`, 오른쪽은 저장 상태 · 보조 동작(고스트) · `발행하기` · 속성 패널 아이콘 토글. 제목 34px, 본문 폭 760px.

**hydration 주의.** 서버에서 렌더한 Base UI `ContextMenu`와 테마 버튼이 뒤따르는 요소의 `useId`를 서버와 다르게 만들었다. 둘 다 hydration이 끝난 뒤에 실제 요소를 그린다(`ActionContextMenu`, `ThemeToggle`).


**표 폭·스크롤.**

- **스크롤바:** 관리자 화면에 `color-scheme`을 두고 스크롤바를 얇게, 평소엔 투명하게 한다(다크 모드에서 흰 기본 스크롤바가 보이던 문제).
- **열 너비 조절:** 머리글 오른쪽 가장자리를 끌거나, 손잡이에 초점을 두고 ←/→로 16px씩 바꾼다. 두 번 누르면 기본 너비로 돌아간다. 너비는 컬럼 설정(`columns.sizes`)에 저장한다.
- **제목 폭:** 너비를 정하지 않은 제목은 남는 폭을 채운다. 어느 컬럼이든 끌기 시작하면 그 순간의 제목 너비를 고정한다. 그래야 끄는 컬럼만 커지고 손잡이가 커서를 그대로 따라간다(전에는 제목이 줄어들며 폭을 흡수해 손잡이가 커서보다 더 움직였다). 그 뒤 남는 폭은 `⋯` 칸 앞의 빈 칸이 받고, 합이 화면보다 넓으면 가로로 스크롤한다.
- **좁은 폭:** 기본 너비로 제목이 240px을 못 받으면 폴더 → 주소 → 생성일 → 발행일 → 태그 순으로 숨긴다. 사용자가 넓힌 너비로는 숨기지 않는다(끄는 도중 다른 컬럼이 사라지지 않게).

**폴더 탐색.** 파일 탐색기처럼 동작한다(v1 §3.3의 `전체`·`미분류`를 바꿈).

- 사이드바 트리의 뿌리는 컬렉션 이름(`메모`)이고, 폴더는 그 아래에 연결선(`├`·`└`)으로 이어진다. 폴더 아이콘이 펼침 단추를 겸해(올리면 화살표) 따로 화살표 자리를 비우지 않는다. `미분류`는 없다. 예전 주소의 `folder=unfiled`는 최상위로 읽는다.
- 탐색 모드(검색·필터·"하위 폴더 포함"이 모두 꺼짐)에서는 현재 위치의 하위 폴더와 바로 든 항목만 보인다. 최상위는 최상위 폴더와 폴더 밖 항목이다.
- 검색·필터를 걸거나 "하위 폴더 포함"을 켜면 현재 위치 아래의 모든 항목을 평평하게 보여 준다. 폴더 컬럼이 꺼져 있으면 제목 옆에 폴더 경로를 작게 붙인다.
- 폴더 메뉴(새 하위 폴더·이름 변경·이동·삭제)는 사이드바와 목록의 폴더 줄이 같다(`folderMenuActions`).
- 폴더를 지우면 폴더만 없어지고, 바로 든 항목과 하위 폴더는 한 단계 위(최상위면 뿌리)로 옮겨진다. 확인 창과 완료 알림에 옮겨 갈 곳을 적는다.
