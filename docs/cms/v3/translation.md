# CMS v3 — 번역 화면 개선 설계

작성일: 2026-09-29 · 상태: **구현 완료(2026-09-29)** · 브랜치: `claude/editor-layout-toolbar-improvements-47d8e3`

> 지금 구조는 [`v2/b4-i18n.md`](../v2/b4-i18n.md), 처음 메모는 [`CMS-V2-SPEC.md`](../../../CMS-V2-SPEC.md) §8. 이 문서는 사용자와 정한 결정(2026-09-29)과 구현 설계·순서다.

## 0. 문제

1. 언어 전환(KO 버튼)이 편집 화면 상단바 왼쪽에 있어 찾기 어렵고 자리가 어색하다.
2. 목록에서 원문과 번역본이 각각 다른 줄이라, 같은 글의 KO와 EN이 멀리 떨어져 헷갈린다.
3. 번역본을 만들면 원문 전체가 복사된 채 일반 에디터로 열린다. 원문과 나란히 보며 블록마다 번역하고, 원문이 바뀐 곳을 알 수 없다.

## 1. 결정

| # | 주제 | 결정 |
| --- | --- | --- |
| 1 | 언어 전환 위치 | 상단바의 언어 메뉴를 없애고 **본문 제목 위 언어 탭**(`KO 원문 · EN 초안 · + JA`)으로 옮긴다. 탭마다 상태(발행·초안)와 원문 변경 수를 보인다 |
| 2 | 목록 | **글 하나(번역 묶음)당 한 줄.** 언어 칸에 KO·EN·JA 표시(발행·초안·없음), 누르면 그 언어 편집으로 간다 |
| 3 | 목록 일괄 작업 | 휴지통·보관 등은 **묶음 전체**에 적용한다. 번역본 하나만 지우기는 편집 화면 언어 탭 메뉴의 `이 번역본 삭제`로 한다 |
| 4 | 번역 편집 방식 | 원문(왼쪽, 읽기 전용)과 번역(오른쪽)을 **번역 단위마다 한 줄씩** 나란히 놓는다 |
| 5 | 구조 | 번역본의 블록 구조는 원문과 **1:1 고정**이다. 번역본에서 블록을 더하기·빼기·옮기기 하지 않는다 |
| 6 | 번역 단위 | 상자 블록(콜아웃·접기·탭·단 나누기·정렬)은 펼친다: 제목·탭 이름은 `머리 줄` 하나, 안쪽 블록은 각각 한 줄. 목록·표·인용은 통째로 한 줄 |
| 7 | 새 번역본 | 모든 줄이 **빈칸(미번역)**으로 시작한다. 이미지는 원문 이미지를 그대로 쓰고 alt·캡션만 빈칸이다. AI 번역은 AI 기능(D2)을 붙일 때 줄마다 버튼으로 더한다 |
| 8 | 코드·차트·수식·다이어그램 | 주석·라벨이 있어 **번역 대상**이다. 줄마다 `원문 복사`로 원문을 번역 칸에 넣고 고친다 |
| 9 | 이미지 | 기본은 원문 이미지. 필요하면 그 언어용 다른 이미지로 바꾼다 |
| 10 | 원문 변경 | 바뀐 줄에 `원문 변경됨`을 표시하고, 누르면 원문의 바뀌기 전·후를 보여 준다. 일괄 적용은 없다. 표시는 **그 줄 번역을 고치면** 사라지고, 번역에 영향 없는 변경은 `변경 무시`로 지운다 |
| 11 | 발행 | 번역본에 **미번역 줄이 있으면 발행을 막는다**(`translation_incomplete`). `원문 변경됨` 줄은 막지 않는다 |
| 12 | 발행 후 원문 변경 | 원문 발행은 막지 않는다. 이미 발행된 번역본은 그대로 공개된다. 번역본 편집 화면·목록·언어 탭에 `원문 변경 N`을 보인다. 원문에 새로 생긴 블록은 번역본에 미번역 줄로, 원문에서 지운 블록은 번역본에서도 빠진다 |

## 2. 번역 단위

### 2.1 나누기

원문 MDX를 파싱해(`analyze` → CMS 문서) 앞에서부터 차례로 번역 단위 목록을 만든다. 순수 함수이고 서버·브라우저가 같이 쓴다(`src/cms/core/translation/units.ts`).

| 블록 | 단위 |
| --- | --- |
| 문단, 제목(H2~H4) | 하나씩 |
| 목록, 표, 인용 | 통째로 하나 |
| 코드, 수식, 다이어그램, 차트 | 하나씩(내용 전체) |
| 이미지 | 하나(alt·캡션·이미지 교체) |
| 콜아웃·접기·탭 | 번역할 속성(제목·탭 이름)이 있으면 `머리 줄` 하나 + 안쪽 블록을 같은 규칙으로 펼친다 |
| 단 나누기, 정렬 | 머리 줄 없이 안쪽만 펼친다 |
| 구분선 | 번역할 것이 없다. 줄로 보이되 늘 `번역됨`이다 |

제목·요약·SEO 같은 언어별 필드는 지금처럼 제목 입력·속성 패널에서 고친다. 제목 입력은 원문 제목을 자리 표시로 보인다. 필드의 원문 변경 추적은 이번 범위에서 뺐다(필요하면 필드 줄로 더한다).

### 2.2 단위의 이름표

단위마다 `경로`(상자 안 몇 번째인지, 예: `3/tab:1/0`)와 `종류`, `원문 조각`(그 단위의 원문 MDX 텍스트)을 가진다. 본문 MDX에는 블록 ID를 넣지 않는다(CMS-V2-SPEC §8).

## 3. 저장

### 3.1 번역 상태

`entry_bodies`에 `translation JSONB NULL` 열을 더한다(원문은 NULL). working·published가 각자 가진다.

```ts
type TranslationState = {
  version: 1;
  units: {
    kind: string;          // "paragraph" | "heading" | "list" | "code" | "image" | "header:tabs" …
    source: string;        // 번역할 때 기준으로 삼은 원문 조각(바뀌기 전·후 비교에 쓴다)
    target: string | null; // 번역 결과 MDX 조각. null = 미번역
  }[];
};
```

- 번역본의 `mdx`는 이 목록과 원문 뼈대에서 **만들어 낸 값**이다. 미번역 단위는 빠진 채로 만든다(미리보기용). 발행은 미번역이 0일 때만 된다.
- 자동 저장·브라우저 복구본·충돌 검사 지문(`formFingerprint`)에 `translation`을 포함한다.
- 발행하면 working의 `translation`이 published로 함께 복사된다.

### 3.2 원문과 맞추기

번역 화면을 열 때 **원문의 최신 초안**으로 단위 목록을 다시 만들고, 저장된 `units[].source`와 맞춘다.

1. 경로·종류가 같고 원문 조각이 같은 쌍을 순서를 지키며 최대한 맞춘다(최장 공통 부분열).
2. 맞춰진 단위 사이에 남은 쌍 중 경로·종류가 같은 것 → `원문 변경됨`(번역은 유지).
3. 원문에만 있는 단위 → `미번역` 줄.
4. 번역에만 남은 단위 → 버린다(원문에서 지운 블록).

`원문 변경됨`은 저장하지 않고 매번 계산한다(`source` ≠ 지금 원문 조각). 번역을 고치거나 `변경 무시`를 누르면 그 단위의 `source`를 지금 원문 조각으로 바꿔 표시를 지운다.

### 3.3 기존 번역본

이전하지 않는다. 지금 있는 번역본은 테스트용이라 지우고 시작한다(2026-09-29 사용자 확인). `translation`이 NULL인 번역본은 열 때 모두 `미번역`으로 시작한다.

## 4. 화면

### 4.1 언어 탭(결정 1)

- 제목 입력 위에 탭 줄: 언어 이름 + 상태 점 + `원문 변경 N`/`미번역 N`. 없는 언어는 점선 `+ JA`(누르면 빈 번역본을 만들고 그 탭으로 간다).
- 탭 메뉴(…): `이 번역본 삭제`(번역본만). 원문 탭에는 없다.
- 상단바의 `LanguageMenu`는 없앤다.

### 4.2 번역 편집(결정 4~11, 2026-09-29 개정)

처음엔 원문·번역을 줄마다 나란히 쌓았으나, 상자 블록(콜아웃·탭)의 모양이 보이지 않아 읽기 어려웠다. 사용자 제안으로 바꿨다.

- 원문 탭은 지금 에디터 그대로. 번역 탭은 **실제 글 모양의 미리보기 + 오른쪽 번역 패널**이다.
- 미리보기(`translation-preview.tsx`): 번역한 블록은 번역문, 미번역은 원문을 흐리게(점선), 원문 변경은 노란 바탕. 블록을 누르면 그 단위를 고른다. 상자 제목·탭 줄을 누르면 머리 줄을 고른다. 누른 자리는 번역본 문서를 만들며 남긴 노드별 단위 기록(`buildWithOwners`)과 에디터 문서를 나란히 따라가 찾는다(`unit-ranges.ts`).
- 위 막대: 진행률, `원문으로 보기`(미리보기 전체를 원문으로), `다음 미번역`.
- 패널(`translation-panel.tsx`, 오른쪽 사이드바, 좁은 화면은 덮개): 위치(`콜아웃 안 · 2/9`), 이전·다음, 원문 미리보기, 원문 변경됨(비교·변경 무시), 번역 편집기(비어 있으면 `미번역`), `원문 복사`·`저장`(Cmd/Ctrl+Enter). 다른 블록으로 옮길 때 고친 내용을 자동 저장하고, 원문과 다른 종류의 블록이면 옮기지 않고 오류를 보인다.
- 번역 편집기는 원문과 같은 종류·구조에서 글자만 비운 뼈대로 시작한다. 1:1 구조는 저장할 때 검사한다(`블록 하나만`, `같은 종류의 블록만`).
- 서식 도구 줄과 `MDX` 전환은 번역 탭에서 두지 않는다.

### 4.3 목록(결정 2·3)

- 목록 API에 묶음 보기(`group=translation`)를 더한다: 원문 한 줄 + `translations: [{ locale, id, status, staleCount, missingCount }]`.
- 정렬·폴더·카테고리·태그는 원문 값으로 한다. 검색은 묶음 안 어느 언어 제목에 걸려도 그 줄을 보인다.
- 언어 필터는 `EN 있음 / EN 없음`처럼 번역 현황으로 바뀐다.
- `staleCount`·`missingCount`는 보이는 쪽(한 페이지)만 서비스에서 계산한다(블로그 규모).
- 일괄 휴지통·보관·복원은 묶음 전체. 영구 삭제도 묶음 전체(지금의 `has_translations` 제약은 묶음 삭제에서는 함께 지운다).

## 5. 구현 결과(2026-09-29)

- 1단계 `d8f1f4a3`, 2단계 `6b4913b1`, 3단계 `ccb717bf`, 4단계는 이 문서와 같은 커밋.
- 번역 상태는 폼의 `$translation` 키(JSON 문자열)로 자동 저장·복구본·충돌 비교에 함께 실린다(`translation-rows.ts`). 번역 화면은 열 때 원문과 다시 맞추고, 결과가 저장된 값과 다르면(원문에 블록이 더해지거나 빠짐) 바로 저장 대상으로 만든다.
- 운영 DB에는 `pnpm cms:db:migrate`로 `entry_bodies.translation` 열을 더해야 한다.

## 6. 순서

1. **목록·언어 탭(결정 1~3):** 묶음 목록 API·UI, 언어 탭, 번역본만 삭제, 묶음 일괄 작업. 번역 편집 방식과 독립이라 먼저 한다.
2. **번역 단위(§2):** 나누기·원문 조각·맞추기 순수 함수와 테스트(글 49편으로 나누기·다시 합치기가 원문과 같은지).
3. **저장(§3):** `translation` 열, 저장·자동 저장·충돌·발행 규칙(`translation_incomplete`), 빈 번역본 만들기, 기존 번역본 이전.
4. **나란히 보기(§4.2):** 줄 목록, 단위 에디터, 원문 복사·비교·변경 무시·이미지 바꾸기, 원문 변경 수.
5. 공개 화면 확인(번역본 렌더·hreflang은 그대로여야 한다).

## 7. 확인이 남은 것

- 표를 통째로 한 단위로 두면 큰 표는 칸이 길어진다. 실제 글에서 불편하면 표만 칸 단위로 나눈다.
