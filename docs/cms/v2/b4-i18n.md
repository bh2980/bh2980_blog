# CMS v2 — B4. 다국어 콘텐츠 구조 작업 계획

작성일: 2026-09-27 · 상태: **진행 중** · 브랜치: `feature/cms-v2`

> 범위와 결정은 [`CMS-V2-SPEC.md`](../../../CMS-V2-SPEC.md) §3.4에 있다. 이 문서는 구현 설계와 순서다.

## 1. 언어 설정

`src/libs/i18n/locales.ts` 한 곳: `LOCALES = ["ko", "en", "ja"]`, `DEFAULT_LOCALE = "ko"`, 언어 이름·`hreflang`·OG `locale`·날짜 형식. 관리자와 공개 블로그가 같이 쓴다.

## 2. 데이터 모델

### 2.1 게시글·메모(`publish` 컬렉션): 언어별 문서 + 번역 묶음

| 열 | 뜻 |
| --- | --- |
| `entries.locale` | 이 콘텐츠의 언어. 기존 행은 `ko` |
| `entries.translation_group_id` | 번역 묶음. **원문의 ID와 같다.** 기존 행은 자기 ID |
| `content_addresses.locale` | 주소의 언어. 기본 키가 `(collection, locale, slug)`로 바뀐다 |

- 원문은 `id = translation_group_id`인 콘텐츠다. 원문 언어가 `ko`가 아니어도 된다.
- 묶음 안에서 언어마다 하나(`UNIQUE (translation_group_id, locale)`). 휴지통에 있는 번역본도 자리를 차지한다.
- 초안·발행·예약·보관·휴지통·자동 저장·충돌 검사는 번역본마다 v1 그대로다.
- **번역본은 언어별 값만 저장한다.** 정의(B1)에서 `localized`가 있는 필드(제목·요약·SEO·주소)만 받고, 공통 필드(카테고리·태그·정책·대체 글·표시 발행일)는 거부한다. 공통 값은 원문에서 읽는다.
- 번역본 발행은 **원문이 공개돼 있을 때만** 된다(`source_not_published`). 공개 화면의 카테고리·태그·날짜가 원문 공개본에서 오기 때문이다. 원문이 공개에서 빠지면 번역본도 공개 목록·주소에서 빠진다.
- 원문을 영구 삭제하려면 번역본을 먼저 지워야 한다(`has_translations`).

### 2.2 카테고리·태그·모음집(`record` 컬렉션): 한 레코드 안의 언어별 이름

- 메타데이터 `translations: { en: { title, summary }, ja: { ... } }`. 정의에서 `localized`인 필드만, 기본 언어는 넣지 않는다.
- 주소(slug)와 연결 관계는 공통이다. 언어별 이름이 없으면 기본 언어 이름을 쓴다.

### 2.3 번역본 만들기

`POST /entries/{id}/translations { locale }`: 원문(묶음의 원문)의 최신 초안에서 언어별 값과 본문을 복사한 초안을 만든다. 주소는 원문 주소를 그대로 쓰고(언어가 달라 겹치지 않는다) 바꿀 수 있다. 폴더는 원문과 같다. D2(AI 초벌 번역)는 이 요청에 옵션으로 붙인다.

## 3. 관리자

- 목록: `언어` 컬럼과 헤더 필터(`locale` 매개변수). 기본은 모든 언어.
- 편집 화면 머리글: 언어 표시와 같은 묶음의 언어 사이 이동, 없는 언어는 `번역본 만들기`.
- 번역본 속성 패널: 언어별 값만 입력, 공통 필드는 원문 값을 읽기 전용으로 보여 주고 원문으로 가는 링크를 둔다.
- record 대화상자: 언어별 이름·설명 입력.

## 4. 공개 블로그

- 주소: 기본 언어는 지금 그대로, 그 밖은 `/en/...`·`/ja/...`(`src/app/(blog)/[locale]`, 알 수 없는 언어는 404). 페이지 본체는 언어를 인자로 받는 공용 컴포넌트로 옮기고 두 경로가 함께 쓴다.
- `<html lang>`: `src/proxy.ts`가 요청 경로의 언어를 헤더로 넘기고 루트 레이아웃이 읽는다.
- 번역이 없는 글은 그 언어의 목록·RSS·sitemap에서 빠지고 주소는 404.
- `hreflang`: 글 화면은 공개된 번역본끼리, 목록 화면은 언어별 목록끼리 연결한다. 기본 언어 주소가 `x-default`.
- sitemap: 한 파일에 모든 언어 주소를 넣고 항목마다 `alternates.languages`를 단다(검색엔진 권장 방식). RSS: `/rss.xml`(기본 언어), `/en/rss.xml`, `/ja/rss.xml`.
- 본문 내부 링크 `/posts/slug`: 렌더할 때 같은 언어 번역본이 공개돼 있으면 그 주소로 바꾼다. 본문은 고치지 않는다.
- 문구 사전: `src/libs/i18n/messages/{ko,en,ja}.ts`. 공개 화면의 고정 문구를 모두 사전으로 옮기고, `en`·`ja`에 없는 문구는 `ko`로 보인다. 날짜는 `Intl.DateTimeFormat`에 언어를 넘긴다.

## 5. 작업 순서

1. 언어 설정, DB 열·기본 키 이전(여러 번 실행해도 같은 결과), 저장소·서비스·스냅샷 규칙, API(번역본 만들기, 상세의 묶음 정보, 목록 `locale`), 내보내기 manifest. 테스트.
2. 관리자 UI.
3. 공개 블로그(라우트, 조회, 링크, `hreflang`, sitemap·RSS, 문구 사전).

## 6. 완료 조건

- 기존 데이터가 그대로 `ko` 원문으로 보이고 주소·리다이렉트가 바뀌지 않는다.
- 번역본을 만들고 발행하면 `/en/...`에 보이고, 원문과 서로 `hreflang`으로 연결된다. 번역이 없는 언어 주소는 404다.
- 전체 테스트·타입 검사·Biome·빌드 통과, 브라우저 확인.
